# 管理页面层级与 Linux 用户管理重构方案

状态：第一阶段已进入实现并完成自动化回归；第二、第三阶段继续作为后续计划。具体交付范围、验证证据及待验收项见[第一阶段实施记录](../engineering/linux-user-page-hierarchy.md)。

## 1. 问题与反思

当前“我的运行环境”把创建/验证账号、升级/移除 daemon、账号列表、展开详情、CLI 安装和操作历史放在一条长页面中。详情中的动作又回填页顶公共表单，用户必须离开正在查看的账号才能继续操作。

这是信息架构错误，不能仅靠减少文案、折叠更多区块或改按钮位置解决。

原因来自本轮实现方式：

1. 按 API 和功能清单逐项往已有页面追加控件，未先确定用户进入页面时的主要任务。
2. 将复用表单和组件等同于复用操作入口。代码复用有价值，但不应要求用户用一个“操作”下拉框理解不同生命周期动作。
3. 验证重点放在权限、请求、错误和状态回归，缺少列表浏览、返回、账号上下文和首屏负担的验收。
4. 功能从简单开通扩展成资源管理后，仍沿用原来的表单页面，没有及时改为列表与详情结构。

项目、智能体和运行时模块已有分层模式。技术栈与现有导航并不妨碍采用它们，应在新增管理功能前先确定入口、详情及操作反馈的层级。

## 3. 统一页面规则

- 资源集合：首页先回答“我有哪些、哪个有问题、进入哪一个”；页头放主要创建动作。
- 复杂资源详情：独立可定位的页面，保留返回列表入口。账号、Computer 的长期管理不用行内无限展开，也不塞进大型弹窗。
- 短操作：新建、接入、安装、升级、危险确认用聚焦的 Dialog / AlertDialog。操作对象固定展示，用户不再选择对象后切换通用“操作”枚举。
- 普通设置：单个对象的资料表单、小型批量编辑仍可留在一页，不为所有字段和简单对象增加详情层。
- 异步任务：区分“请求已接受”和“执行成功”。进度与错误归属于操作对象，离开页面不取消已接受的远端任务。
- 导航用链接，动作使用按钮；详情/页签/筛选进入 URL，密码和密钥不得进入 URL、持久化草稿或导航 state。
- 小型列表不提前加入复杂筛选器。Linux 用户支持按用户名或 Computer 搜索；大型列表的分页沿用 API 能力，不在此轮引入通用表格平台。

## 4. 我的 Linux 用户：列表 → 详情 → 操作

将设置个人分组的侧栏名称和页面标题统一为“我的 Linux 用户”。保留 `tab=computers`，不迁移 URL key；旧书签仍进入同一模块。工作区分组保留“Linux 用户”，页内标题为“我接入此工作区的 Linux 用户”；“个人凭据”页内明确“个人凭据模板”。名称变更同步五种语言，不用重复副标题解释名称。列表是本人全账号范围，不因当前工作区路由只显示当前工作区的账号。

```text
我的 Linux 用户                                    [+ 新建 Linux 用户]
[搜索用户名或 Computer]

Linux 用户       Computer       工作区          状态              操作
mas              gpu-pc         产品研发         创建失败          详情
alice            dev-server     产品研发         待配置            详情
build            gpu-pc         产品研发         已移除托管        详情
worker           gpu-pc         原工作区已删除   工作区已解除关联  详情
```

示意数据不是线上状态。窄屏使用同样字段的紧凑列表项，不堆叠出第二套操作逻辑。

列表只展示用户名、Computer 名称、工作区名称、摘要状态与“详情”。错误标记可以点击进入对应操作，不输出完整英文错误或工作区 UUID。无权查看/已删除的工作区显示合适的占位状态，不额外暴露资料。

摘要状态必须保留业务差别；账号状态与操作结果不能压成一个“失败”：

| 条件 | 列表显示 | 下一步与限制 |
| --- | --- | --- |
| 存在未过期 queued/running 操作 | 正在创建 / 正在安装等具体动作 | 进入操作记录；不能并发执行互斥操作 |
| 有超时未确认操作或 binding 为 interrupted | 需确认中断 | 先确认远端结果并走现有恢复流程；不能直接重试覆盖 |
| 无上述操作，account_state=missing/unavailable 或 verified=false | 账号不存在 / 账号不可用 / 未验证 | 提供重建、检查或验证；下方仍可说明绑定状态 |
| verified=true、账号无已知异常、binding=pending | 待配置 | 进入详情配置凭据或启动 daemon；不等同于账号失败 |
| binding=removed，账号无已知异常 | 已移除托管 | 满足验证、主机可用和无冲突等条件后可重新接入；不能据此推断账号已删除 |
| binding=detached，账号无已知异常 | 工作区已解除关联 | 原工作区已删除，需选择可用工作区重新接入；不表示远端 daemon 已确认停止 |
| binding=ready，账号无已知异常 | 已就绪 | 详情单独显示 daemon 最近观测状态；不把历史 ready 当作实时在线 |
| binding=failed | 显示具体失败动作；未知时“最近操作失败” | 按操作记录给出恢复动作，不推断 Linux 账号不存在 |

上表按操作进行中/待恢复优先，再判断账号事实和绑定状态。独立 runtime 操作失败可能不改变 binding 状态：在原有摘要旁追加“CLI 安装失败”等具体提示并链接相应记录，不能把账号改画成“创建失败”。

`pending` 仅能证明账号创建/验证后尚未由此流程确认 daemon 就绪，不能证明哪个凭据缺失，也不能推断 daemon 一定离线。此时推荐“完成配置”，详情同时提供账号凭据与启动入口，依据已有安全错误码（例如 credentials_required）再指引具体步骤，不为绘制列表主动读取密钥。`removed` 和 `detached` 都可能重新接入，区别是解除原因与工作区关联，不是“只有 removed 能复用”。详情完整保留账号、绑定、daemon 和操作四层事实。

空列表给出“新建 Linux 用户”，无可用 Computer 则说明联系管理员登记主机，不能只给不可点击按钮。

### 4.1 新建弹窗

只包括 Computer、Linux 用户名、Linux 密码（可显示）、接入工作区。工作区默认当前工作区，只允许选择本人仍是成员的工作区；没有可用工作区时给出明确下一步。

当前 `create_account` 仍要求工作区，本方案不借 UI 重构引入“无工作区建号”或新实体。需清楚告知创建账号同时建立工作区关联，但不自动写凭据、安装 CLI 或启动 daemon。

为避免已有服务器账号用户误解，创建/验证使用同一弹窗，说明密码分别用于设置新账号密码或验证现有账号密码。现有 API 会在账号存在时验证，页面不得承诺强制创建或改密，也不能在未验证前泄露他人账号归属。“已由 Multica 验证的本人账号接入”继续走工作区接入入口。

提交后等待 API 接受，成功才关闭弹窗并进入该账号详情，展示正在创建/验证。API 拒绝时保留输入与错误；关闭后清除密码。操作失败保留记录，通过详情的“重试创建/验证”重新输入密码，不让用户回列表顶部拼参数。

### 4.2 账号详情

```text
我的 Linux 用户 / mas
mas · gpu-pc                         [按状态提供一个主要下一步] [更多]
工作区：产品研发

[概览] [CLI 运行时] [账号凭据] [操作记录]
```

| 页签 | 负责什么 | 不放什么 |
| --- | --- | --- |
| 概览 | 账号与工作区关系、账号检查、daemon 状态、最近操作摘要、明确下一步 | 所有 CLI 的完整安装表单、所有操作日志、凭据明文 |
| CLI 运行时 | 已安装/未安装列表，版本和可用性；“安装/更新”打开该 runtime 的小弹窗，版本可留空 | 每行常驻版本输入框、重复的安装说明、完整诊断元数据 |
| 账号凭据 | 显示目标账号；显式验证密码后读取远端，编辑并写入该账号；可主动载入个人模板 | 另选目标账号、静默拉取远端密钥、默认保存为个人模板 |
| 操作记录 | 进度、步骤、时间、结果、错误恢复；完整记录可展开，支持直接定位某次操作 | 密码、Token、原始 SSH 输出 |

CLI 路径、安装来源、最近探测等资产详情按需展开；显示已安装与工作区已注册的区别。数据刷新与远端重新探测使用不同文案，避免两个“刷新”含义不同。

daemon 启动/升级在详情打开专用密码弹窗，不回填列表页。缺少 PAT 时提供“配置账号凭据”链接。正在执行互斥操作时说明原因，详情浏览仍可用。

移除托管、归档和删除 Linux 用户放在明确的生命周期入口与确认弹窗；入口按资格显示，依赖顺序不能藏在模糊的“更多”里。删除 home 的后果和必须先移除 daemon 的条件始终在相应动作旁说明。移除 daemon 不等于删除 Linux 用户。

## 5. 凭据按归属分开

当前版本切换账号已经清除草稿、来源、模板导入确认、明文显示和密码；本轮解决模板与远端编辑职责混合，并补齐分区导航和迟到响应的生命周期边界。

“个人凭据”只管理个人模板，不再放 Computer/账号选择器、Linux 密码和远端读写。字段按 Git 身份、代码仓库认证、模型服务和 Multica Token 分组，必要帮助放在对应字段，只有一个“保存个人模板”动作。

远端读写归“Linux 用户详情 → 账号凭据”，显示固定的 `Computer · username`。页签默认不读取明文，不因进入详情就加载个人模板或远端密钥。操作草稿只存当前内存，按下述生命周期清除。

保留双向能力但改成明确动作：

- “载入个人模板”：主动复制到当前账号草稿；不会写服务器，需点击“写入此 Linux 用户”。已有编辑时确认替换。
- “从服务器读取”：密码验证后回填当前账号草稿；不会改变个人模板。
- “保存为个人模板”：次要操作，明确确认替换个人模板及复用远端密钥的影响；不会顺便写服务器。

### 密码与凭据草稿生命周期

- Linux 密码只放在实际需要验证的操作弹窗或凭据页签组件内，不挂在详情页父容器、全局 store 或跨页签草稿中。现有 CLI 安装通过账号所有权授权，并不要求 Linux 密码；本次不扩大其认证范围。
- 关闭弹窗、离开凭据页签、切换 binding、退出详情、退出登录均销毁对应敏感状态并重置 mutation；重新打开默认隐藏，必须重新输入密码。
- 凭据页签切到其他页签时不使用保活隐藏面板。若有未保存编辑，离开前明确提示会丢弃；取消离开保留当前编辑，确认离开才清除密码、远端草稿及模板导入确认。
- 请求完成后尽快清空提交的密码；请求在途时离开不会取消已被服务端接受的工作，但迟到的读取响应不得回填已卸载/已切换账号的组件，也不得落入持久化 Query/mutation 缓存。
- Desktop 若后台页签仍挂载，须核实其可见性生命周期；窗口切到其他应用页签或账号上下文变化时清除敏感内容。普通导航状态可恢复，明文凭据不可随页签恢复。
- “清除内存”指销毁应用持有的状态、引用及缓存，并防止迟到响应重新写入；JavaScript 无法承诺对已经分配的字符串立即执行物理内存擦除。

沿用已实现的非空字段合并、归属校验、禁止缓存和无密钥审计。此次不增加多模板实体、密钥保险库或跨账号批量同步。

## 6. 其他页面如何一起调整

### 工作区 Linux 用户

首页只展示“我接入此工作区的 Linux 用户”，页头“接入 Linux 用户”。这一轮不把同工作区其他人的私有 Linux 账号混入列表，也不扩大读取权限。

接入弹窗提供“选择本人已有账号”与“创建/验证服务器账号”。可复用同一创建组件，工作区固定为当前工作区；跨工作区占用项说明需先在哪个工作区移除受管 daemon。中断操作指向该账号操作记录，不要求用户从个人首页重新查找。

操作结束回到当前工作区列表；继续配置链接直接打开个人账号详情，保留可理解的返回入口。查看账号详情不隐式切换其所属工作区，真正跳转工作区资源时才使用跨工作区导航适配器。

### Admin Area

Computer 列表保留名称、SSH 地址、启用状态、最近检查结果、绑定账号数以及详情入口。注册使用已有弹窗；创建者、登记时间、完整检查结果、编辑和关联账号进入 Computer 详情。列表可保留“测试连接”快捷动作，其结果进入详情的检查记录区。

Admin Linux 用户列表保留账号、Computer、所有者、工作区和状态。详情使用管理员展示模式，查看操作/检查信息；不给管理员个人凭据入口，也不复用所有者的写配置或删账号能力。实例审计继续作为独立检索入口，从对象详情可跳到已筛选的审计记录。

Admin 当前 section 与展开项由本地 state 管理，需要一起改为可刷新/返回的 URL 状态。保持已有 Admin 入口，不新增一个全局管理平台。

### 成员、API Token

只把邀请/创建常驻表单移动到页头按钮对应的弹窗。成员邀请、角色修改、移除与 Token 单次展示、撤销沿用现有权限及确认流程。不因为追求整齐而增加缺乏内容的详情页。

### 已有分层的页面

项目、智能体、运行时、集成沿用已有层级。运行时仅在能可靠解析所属受管 binding 且当前人有权管理时提供“管理 Linux 用户”链接；无映射或属于他人的运行资源不提供越权账号链接。独立注册 daemon 不强行映射为 Computer/Linux 用户。

不在本轮另建全局工作区管理中心。工作区通用设置本身是单对象配置，不能仅因表单较长判定为列表/详情混层。

## 7. 导航与数据契约

### 7.1 URL 命名与清理

设置内采用可直达的子页面，保留设置侧栏：

- 列表：`?tab=computers`，可附 `linux_user_search=<text>`。
- 详情：`?tab=computers&linux_user=<binding-id>&linux_user_view=overview|runtimes|credentials|operations`。
- 指定记录：仅在 operations 分区附 `operation=<id>`；记录必须属于当前 binding。
- 从当前工作区接入列表进入：附 `linux_user_from=workspace`。个人列表或直接打开不带该参数，默认个人列表来源。来源只接受固定枚举，不接受任意 return URL。

不复用现有 `section`：它已用于偏好设置等子页。`settingsHref` 和专用的 `resolveLinuxUserLocation` 在 1A 一起扩展，设置模块入口仍由 `resolveSettingsLocation` 解析，集中维护 Linux 用户参数集合：`linux_user`、`linux_user_view`、`operation`、`linux_user_from`、`linux_user_search`。

离开 `tab=computers` 时删除上述参数，同时维持已有 `section` / `integration` 清理与无关回调参数保留逻辑。返回个人列表删除详情 ID、分区、操作和来源，保留个人列表搜索。切换详情分区时移除过期 operation，只有操作记录链接可以显式带入它。缺少 binding 时忽略孤立的分区/操作参数；未知 view 回到 overview，未知来源回到个人列表。不能使用未知参数触发远端操作。

所有链接通过 NavigationAdapter / AppLink 构造，不直接操作浏览器地址或绕过 Desktop adapter；新建使用工作区会话内 Dialog，不是 pre-workspace WindowOverlay。

### 7.2 返回目标与工作区上下文

- 从个人列表进入：详情顶部显示“返回我的 Linux 用户”，恢复列表搜索和滚动位置。
- 从工作区接入列表进入：显示“返回工作区 Linux 用户”，目标是当前路由工作区的 `?tab=linux-users`；详情分区切换期间保留来源。
- 直接打开详情且没有合法来源：回到当前设置容器下的个人列表，不依赖 `history.back()` 猜测来源。
- 可保留“我的 Linux 用户”作为资源层级面包屑，但它不能替代工作区来源的主要返回入口。
- 查看个人账号详情保持当前路由工作区，不跳到绑定所属工作区。真正跳转工作区资源才调用跨工作区适配器。若当前工作区权限失效，使用现有 workspace guard 处理，不能从来源参数恢复已失效的访问。

浏览器前进/后退保持真实导航历史；页面内“返回列表”使用明确目标。直接链接、浏览器返回和来源明确的返回按钮各自有测试。

### 7.3 Desktop 核查与待验收项

已核对 `apps/desktop/src/renderer/src/platform/navigation.tsx`：push/replace 将完整 path 交给 `navigateActiveSession`，searchParams 从当前 tab URL 解析。`stores/tab-store.ts` 保存 URL 与虚拟历史，并在持久化中保留 tab.url；现有导航测试覆盖 query/hash 解析。没有证据表明多参数 URL 本身不受支持。

这不等于新详情流程已通过 Desktop 验收。1A 必须补：同设置页内多参数 push/replace、前进后退、应用页签切走再切回、持久化恢复、固定页签导航及同资源页签去重时的目标行为。普通跳详情走 push/replace，不用可能保留旧 URL 的 openInNewTab 来模拟页内导航；若显式新开页签，要遵守平台现有去重规则并验证目标。不先添加兼容层，测试证明确有缺口时才调整适配器。

### 7.4 列表响应与工作区名称

现有 GET `/api/me/computer-bindings` 的字段保留，新增以下最小摘要。通过同一次数据库查询的权限受限关联和最近操作子查询获得；不能逐行请求 detail/operation、发起 SSH 或解密凭据。

| 字段 | 含义与兼容默认值 |
| --- | --- |
| workspace_name | 仅当前仍是成员且工作区存在时返回名称，否则空字符串；schema 默认空字符串 |
| workspace_access | accessible / unavailable / none；旧响应或未知枚举回退 unknown |
| latest_operation | 最近操作摘要或 null；旧响应默认 null，畸形摘要整体回退 null，不把部分畸形记录当成功 |
| latest_operation.id / kind / state / error_code / finished_at | 操作 ID、动作、有效状态、安全错误码和完成时间；finished_at 区分尚待确认与已确认的中断；只含元数据，缺失字符串默认空，未知 state 映射 unknown，不臆造“成功”或“中断” |

查询按 `computer_binding.user_id=当前用户` 和未归档过滤。LEFT JOIN workspace 的名称投影须受 membership 存在性限制，不能直接返回被关联工作区的名称。`workspace_access=unavailable` 不区分退出、被移除或记录缺失，避免额外暴露工作区是否仍存在。最近操作可用 LEFT JOIN LATERAL / 等价子查询，按 created_at DESC、id DESC 确定一条，并和现有 operation 列表一致地将过期 queued/running 投影为 interrupted；有效活跃操作由 operation_busy 优先控制。

工作区显示最低契约：

| 数据条件 | 列表显示 |
| --- | --- |
| accessible 且名称非空 | 工作区名称 |
| accessible 但名称缺失，或旧响应有 workspace_id 却无权限/名称字段 | 工作区信息不可用；不推断用户已失去权限 |
| unavailable | 工作区不可访问；不回传名称、成员或其他资料，不显示 UUID |
| none 且 binding=detached | 原工作区已删除；这是本人的 binding 已持有的事实 |
| none 且其他状态 | 未接入工作区 |

Computer 名称和用户名仍可识别账号，不为辨识已失去访问权的工作区新建名称快照或引入历史资料泄露。现有 workspace_id 为 API 兼容保留，但不作为 UI 名称回退。

core schema 对新增字段做默认/未知回退，新增字段畸形不能让整个账号列表消失。补旧响应、未知枚举、无权限工作区、无操作、超时操作、同时间操作排序及多账号只用一次列表查询的回归。若涉及持久 SQL 查询变更，按仓库规则重新生成 sqlc；本阶段不需要新实体或迁移。

Query 管服务端数据，只有编辑/弹窗等临时状态留组件；详情按当前页签加载所需数据，凭据例外必须显式操作才读取。后端状态更新使用现有 operation 流程，不以 UI 乐观状态伪造远端完成。

## 8. 实施拆分与完成标准

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 1A | 列表摘要契约、URL 与页面容器 | 锁定摘要状态及新增响应契约；工作区名按权限投影且不回退 UUID；专用参数清理、两种返回来源和 Desktop 历史/恢复专项测试通过 |
| 1B | Linux 用户列表、创建及账号详情 | 首屏只有列表和创建入口；取消通用操作下拉框、行内完整详情及页顶回填；建号异步状态/失败重试可用 |
| 1C | CLI、账号凭据、daemon、操作记录 | 每个任务在目标账号上下文内完成；页签/账号/弹窗离开清理敏感状态，迟到响应不能串号；保留 latest、密码显示和中断恢复回归 |
| 1D | 工作区接入与个人模板页面 | 共用创建组件；模板与远端配置分开；跨入口能直达同一账号详情，返回路径正确 |
| 2 | Admin Computer / Linux 用户详情与审计联动 | 主机列表收敛；管理员详情权限不扩张；导航可直达；不读取他人凭据 |
| 3 | 成员邀请、Token 创建入口收敛 | 创建操作弹窗化；列表浏览优先；原有权限/撤销/单次密钥展示不回归 |

交互验收包括：已有多个账号首次进入时能直接比较；点击详情后不需滚回另一处表单；新建提交失败保持输入；已接受任务可离开再查看；runtime 安装失败不混淆账号存在性；所有禁用动作有明确原因；长名称和窄屏不溢出；键盘可进入详情、关闭弹窗并恢复焦点；中文及其余四种语言同步。

实现时运行各自的 core、views、handler 定向测试与 Web/Desktop 导航验证。真实主机创建、CLI 安装、密码/凭据读写仍需单独记录验收，不能用单元测试代替。

## 9. 本次审阅建议

第一阶段连贯处理个人账号、工作区接入和凭据归属，后续再按第二、第三阶段推进。个人账号重构不能只移动创建按钮，却保留行内全量详情或账号/模板共用编辑器。

核心选择：列表作为首页；账号详情为页面；新建和执行动作使用小弹窗；个人模板独立，实际账号配置回到账号详情；已有合理分层的模块保持现状。
