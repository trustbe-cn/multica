# Linux 用户与工作区协作 TODO

按[方案](../design/linux-user-workspace-collaboration-plan.md)实施。以下清单记录实施进度；未发布的代码不是已上线能力。现有工作区、任务、评论、项目、智能体 Access、运行时可见性及 `computer_binding` 继续复用；本阶段不新增账号或工作区关联实体，也不扩展为同一 Linux 用户同时服务多个工作区。

当前工作分支已实现任务 1 的判定表与稳定冲突码，以及任务 2-5 的共享 Web/Desktop 入口、可选引导和接入表单。工作区页展示本人接入操作的进行中与失败状态，远端操作历史仍从“我的运行环境”查看。定向前端测试已通过；已增加同机多账号与跨成员隔离的数据库回归，并已在隔离测试数据库执行包含凭据读写和无凭据建号的定向 handler 回归。任务 6 的双人协作/权限回归和任务 7 的真实非生产主机验收仍未完成，因此本清单不表示整条链路已验收。

## 可执行清单

### 1. 契约核对

- [x] 对照 `computer_binding` 的唯一约束、`claimComputerBindingSQL`、`removed`/`detached`/`archived` 状态和现有生命周期操作，写出“可选择”“不可选择但可修复”“不可接入”的判定表。
- [x] 核对同一 Computer 上他人已验证账号的同名冲突、未验证失败记录，以及当前 `409` 无法区分冲突与操作进行中的问题；确定不泄露其他所有者的错误契约。
- [x] 核对工作区创建成功后的 Web/Desktop 导航和上手引导；Desktop 在 `WindowOverlay` 关闭后进入工作区上下文，确定与现有欢迎引导不冲突的接入入口，保证跳过后仍能找回。
- [x] 核对 Computer 可用性与 Workspace 成员资格；凭据不再阻塞账号创建，PAT 只在启动 daemon 时必需；只在确有契约缺口时变更 API/schema，并补齐兼容解析测试。

### 2. 个人 Linux 用户管理

- [x] 将“设置 → 我的运行环境”的账号管理与独立“个人凭据”页面分开；账号标识展示 Computer 名称和 Linux 用户名，列表不按 Computer 合并。
- [x] 保留每个 binding 的账号、daemon、CLI、运行时注册状态及操作历史；同机多账号的安装、清理和刷新按 binding ID 区分。
- [x] Web 与 Desktop 共用视图；完成个人账号列表与详情的定向测试。

### 3. 工作区接入

- [x] 实现基于现有 binding 状态的接入资格展示；被其他工作区占用的本人账号仍可看见原因、移除 daemon 的步骤及对原工作区执行能力的影响，但不能静默迁移或覆盖；同名冲突提示更换用户名，不暴露其他所有者信息。
- [x] 工作区创建成功后增加可跳过的接入提示：选择可用旧账号或输入新账号；没有 Computer、没有个人凭据、账号冲突和远端失败均给出对应下一步。
- [x] 使用现有 Query/mutation 提交 `provision`，以已创建工作区 ID 为目标；异步状态、离开页面及重试沿用操作记录，不把重复点击变成重复建号。
- [x] 从现有工作区也能进入接入流程；工作区的运行时页面沿用既有所有者和可见范围，不增加 Linux 密码或他人账号管理入口。
- [ ] 补齐数据库 handler 与浏览器端回归：创建成功但接入失败、跳过后再接入、旧账号占用和不同 Linux 用户同机接入。
