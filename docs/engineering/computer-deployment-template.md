# Computer 功能部署记录模板

复制本模板到当次发布记录中，填写真实结果；历史记录保留日期，不以旧结果代替当前验证。

| 项目 | 本次值 |
| --- | --- |
| 核对时间 / 操作者 | 待填写 |
| 功能提交 / 分支 | 待填写；未提交工作树须保留可核对的源码清单 |
| 部署目录 | `/home/tiger/bench/multica-deploy` |
| backend 旧 / 新镜像 | 待填写 |
| frontend 旧 / 新镜像 | 待填写 |
| schema_migrations 旧 / 新最新记录 | 待填写；有条件跳过的迁移也要记录 |
| 备份位置 / 恢复约束 | 仅记录路径和策略，不写密码、密钥或数据 |
| 构建与迁移结果 | 待填写，失败不得写成通过 |
| 容器健康与重启数 | 待填写 |
| backend 18000 健康 commit | 待填写 |
| frontend 13000 代理健康 commit | 此值来自后端；前端身份另用镜像标签/构建证据核对 |
| 未登录 Admin API | 预期 401，记录实际状态 |
| 远端 daemon 是否升级 | 待填写；应用发布与远端 daemon 升级分别记录 |
| 非生产真实链路验收 | 主机系统、测试账号、工具链来源、CLI 版本/路径、结果及日志位置 |
| 未覆盖范围 | 例如模型认证、真实任务、浏览器 E2E，逐项说明 |
| 回滚标签 / 迁移处理 | 待填写；有活动远端操作时先停新操作并等待完成，不混跑旧版互斥逻辑 |

应用更新使用部署目录的 `manage`，遵守该目录 `AGENTS.md`。仅更新应用时不重建数据库和网关。存在迁移时先评估备份和回滚；不得把 `down -v` 当作发布步骤。
