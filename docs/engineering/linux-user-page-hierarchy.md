# Linux 用户管理页面分层：第一阶段实施记录

日期：2026-09-26。对应[管理页面重构方案](../design/management-page-hierarchy-plan.md)。本轮交付第一阶段，Admin 详情与审计联动、成员邀请和 API Token 创建入口仍列为第二、第三阶段。

## 页面与入口

- 设置个人分组统一命名为“我的 Linux 用户”。首页是本人账号列表、搜索和右上角新建入口，不再显示通用操作表单或展开整套详情。工作区显示名称或权限受限占位，不显示 UUID。
- 详情采用 `tab=computers&linux_user=<id>&linux_user_view=<view>`，分概览、CLI 运行时、账号凭据、操作记录。切换设置模块清除专用参数；列表搜索保留；同一个设置页面内返回列表恢复滚动位置。
- 从工作区接入列表打开详情带 `linux_user_from=workspace`，返回当前路由工作区的接入列表；直接打开详情默认返回个人列表，不切换到账号所绑定的工作区。
- 新建账号、启动/升级 daemon 和生命周期确认在对应弹窗中完成；账号创建仍要求选择本人有权访问的工作区，不要求先保存凭据。服务器已有账号仍验证密码，不会直接接管或改密。成功接受请求后进入操作记录，不能把接受当成远端完成。
- CLI 安装按行打开小弹窗；版本留空使用 latest，版本输入保留运行时专属的可访问名称。互斥操作与中断恢复提供操作记录入口。
- 工作区 Linux 用户首页保留本人接入列表，接入表单收进弹窗。新建使用共享表单，已有账号按资格展示；占用或待恢复账号直接链接详情。

## 凭据与数据边界

个人凭据页只编辑模板；账号凭据页的目标固定为当前 Linux 用户。进入账号页不会读取个人模板或远端密钥，必须明确执行“载入个人模板”或“从服务器读取”。写入仍只覆盖非空字段。将账号草稿保存为个人模板是独立的次要操作，必须先确认。

凭据编辑器按账号和分区卸载。离开账号凭据、切换账号、退出设置或 Desktop 应用页签切换时清除密码与草稿；迟到的读取结果不能填入新账号。个人模板查询与账号查询已拆开，账号列表不会因观察禁用的模板查询而继续保留模板缓存。凭据 mutation 使用 `gcTime: 0`，完成或卸载时 reset。

详情内切分区和返回列表会对未保存草稿给出确认；浏览器关闭/刷新使用原生 beforeunload 提示。其他导航或历史跳转按卸载清除敏感状态，本轮没有增加跨平台的全局导航阻断器。不能把 JavaScript 状态清理表述为物理内存擦除。

GET `/api/me/computer-bindings` 增加 `workspace_name`、`workspace_access`、`latest_operation`。最近操作含安全元数据及 `finished_at`，用于区分待确认与已确认的中断。单条数据库查询取得摘要，不逐行访问接口或 SSH。只有仍具备成员资格的用户才能从个人列表和详情看到工作区名称；管理员详情保持已有授权范围。

core schema 为新增字段提供缺失、畸形和未知枚举回退。POST 建号的接受响应也经过 schema 校验，获得有效账号 ID 才导航。没有新增数据库表、索引或迁移。

## 部署后人工验收

1. 刷新设置，打开“我的 Linux 用户”：确认列表优先显示，没有顶部通用操作表单；搜索同机不同用户名，分别进入详情。
2. 查看待配置、已移除托管、已解除工作区关联与失败记录，确认状态和下一步没有混成一个失败；从工作区接入入口查看详情再返回，确认上下文正确。
3. 在非生产 Computer 创建测试账号，不保存凭据模板；确认接受后进入操作记录，并根据实际远端结果显示状态。
4. 进入账号凭据，确认未自动加载密钥；分别验证读取、主动载入模板和写入。切分区/账号再回来，确认密码及远端草稿已清除；不要使用生产密钥做跨账号覆盖测试。
5. 在测试账号安装一个 CLI，先留空版本，再使用受支持的指定版本，核对实际版本、操作记录及 daemon 发现情况。
6. Web 与 Desktop 分别人工确认刷新、前进/后退、窄屏、键盘焦点及弹窗错误反馈。

真实主机建号、CLI 安装、凭据传输和完整浏览器/Electron 人工流程尚未验收；自动化测试不替代这些结果。部署状态与回滚镜像记录在 `/home/tiger/bench/multica-deploy/releases/` 中对应提交的记录里。
