# Computer、Linux 用户与运行时验收

适用范围：2026-09-25 的 P0/P1 功能及后续操作恢复修复。部署版本和自动化检查结果见[修复记录](computer-runtime-review-fixes.md)；状态与权限契约见[远端操作设计](../design/computer-remote-operations.md)。

## 准备

使用测试 Computer、专用 Linux 用户和测试工作区。准备一个所有者账号、另一个普通 Multica 用户，以及管理员账号。涉及删除的步骤只使用可丢弃的 Linux 用户；删除账号会删除 home，安装失败也可能影响原有 CLI。

先记录当前应用版本、Computer 和 Linux 用户名。每次操作保留操作 ID；遇到问题记录时间、期望和实际结果。不要在反馈中附密码、PAT、模型密钥或原始凭据。

## 人工验收

| 顺序 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 查看 Admin Area 的 Computers、Linux Users，以及设置中的“我的运行环境”。 | Computer 管理机器连接；管理员可查看 Linux 用户详情、操作与资产状态；用户自己的运行时安装和生命周期操作在“我的运行环境”。 |
| 2 | 在测试 Computer 上开通专用 Linux 用户并绑定测试工作区。 | 操作显示阶段；完成后账号存在、绑定就绪。详情分别展示账号、守护进程服务、CLI 安装和运行时注册。 |
| 3 | 开通或安装期间刷新页面、关闭后重新打开；尝试再次提交同一账号操作。 | 后台继续运行，操作记录仍在；重复操作被禁用或返回明确冲突，不会并行执行。 |
| 4 | 安装一个已准备好前置依赖的运行时，并指定已知有效版本。 | 有安装记录、实际版本、路径和时间。需要覆盖全部安装器时，对当前列表中的七种 CLI 逐一执行；不要从一种安装器的成功推断其他种也可用。 |
| 5 | 点击重新发现；选择一个格式合法但已确认不存在的版本测试失败。 | 发现更新检查时间；失败有明确错误，不假报成功、不清空最后已知成功资产。失败后的旧版本是历史记录，应再次发现或重装确认实际产物。 |
| 6 | 对照四层状态，并用已经授权的 CLI 凭据运行一个简单任务。 | CLI 已安装与运行时已注册分开展示。真实任务成功才能证明账号环境、CLI、凭据与模型链路均可用。 |
| 7 | 换另一个普通用户访问该绑定；再以管理员查看。 | 普通用户不能查看或操作他人绑定、资产与操作记录。管理员可检查状态，不能代替所有者安装私有 CLI 或删除 Linux 用户。 |
| 8 | 移除测试账号的守护进程。 | 账号、home、CLI 和历史保留；绑定为 removed，服务已停止。 |
| 9 | 归档已移除的绑定，再通过开通表单重新开通。 | 归档隐藏个人列表条目并保留所有权与历史；重新开通复用同一 binding，重新验证账号。 |
| 10 | 再次移除守护进程，输入用户名和密码删除测试 Linux 用户；随后重新开通。 | 成功删除后为 removed + missing；重新开通实际检查账号并创建，最终为 ready + present。删除有运行中进程的账号应失败并保留可恢复记录，不强杀进程。 |

新安装 CLI 的即时发现需要远端守护进程支持刷新通知。旧守护进程可等待原有周期发现，或显式升级。部署后端不会自动改写所有远端守护进程的二进制及 systemd unit。

## 故障验收边界

不在生产环境人为制造数据库故障、panic 或长期卡死。自动化回归使用独立 PostgreSQL 和测试创建的 SSH/CLI 命令桩，覆盖：

- 审计写入暂时失败时重试终态事务，不重复远端副作用。
- 审计持续失败时保留可恢复记录；提交成功但客户端收到错误时，不重复审计。
- 业务冲突返回 409，数据库连接或超时错误返回 500。
- 同步安装等待对过期 queued/running 返回 interrupted，同时保留互斥占用，等待明确恢复。
- 恢复与 worker 写入按一致顺序加锁；已恢复或过期的旧 worker 不修改新的绑定状态与资产。
- 内外两层 panic 都有操作 ID 和堆栈，日志不包含 panic 的凭据内容。
- 注入的 SSH runner 接收 context 取消及配置的超时。

真实主机验收与命令桩测试是两份证据。完成上述人工步骤后，应在反馈或验收记录中注明实际覆盖的 CLI、版本和环境；未执行的条目保持待验收。
